# 產品需求文件 (PRD)：食譜收藏夾

## 1. 專案概述
- **背景與動機**：常常看到喜歡的食譜或有新的料理靈感，卻因為散落各處而難以尋找。因此需要一個專屬個人的食譜收藏系統，方便統一紀錄、管理與查找。
- **目標用戶**：我自己（個人使用的食譜管理工具）。
- **核心價值主張**：提供一個輕量、簡單且直覺的平台，讓使用者能快速新增食譜、有系統地列出所需材料，並能高效搜尋過往收藏。

## 2. 功能需求
以下為系統主要提供的五項基礎功能，搭配對應的使用者故事（User Story）：

1. **新增食譜 (Create Recipe)**
   - 作為使用者，我希望能夠新增一篇食譜（包含標題、做法等），以便記錄新學到的或自創的菜色。
2. **搜尋食譜 (Search Recipe)**
   - 作為使用者，我希望可以透過關鍵字搜尋食譜標題，以便快速找到我想做的那道菜。
3. **列出材料 (List Ingredients)**
   - 作為使用者，我希望在每篇食譜中，能獨立且清楚地條列所需材料，以便我能快速盤點現有食材或外出採買。
4. **編輯與刪除食譜 (Edit & Delete Recipe)**
   - 作為使用者，我希望可以修改現有食譜的步驟或刪除不再需要的食譜，以便保持收藏夾內容的準確與整潔。
5. **分類與標籤 (Categories & Tags)**
   - 作為使用者，我希望可以替食譜加上分類（例如：中式、西式、甜點等），以便後續依照類型瀏覽或篩選。

## 3. 非功能需求
- **技術限制**：
  - 後端技術：使用 Python + Flask 框架。
  - 前端技術：使用 HTML + CSS (建議 Vanilla CSS + 現代化設計) + Jinja2 模板引擎。
  - 資料庫：SQLite，相當適合這類型單人使用的輕量級在地專案。
- **效能與安全考量**：
  - 雖為單人使用，仍需實作基本的防護機制，如防止 SQL Injection (使用 ORM 或 param binding) 與防止 XSS (Jinja2 預設有跳脫防護)。
  - 核心功能操作流暢，頁面需具備 RWD 響應式設計以便在手機上觀看食譜。

## 4. MVP 範圍 (Minimum Viable Product)
- **Must Have (必須有)**
  - 新增食譜（輸入標題、材料清單、作法）。
  - 條列所有食譜（首頁）。
  - 單一食譜詳細頁面（能清晰閱讀作法與列出材料）。
  - 關鍵字搜尋。
- **Should Have (應該有)**
  - 編輯與刪除現有食譜。
  - 食譜分類/標籤功能。
- **Nice to Have (錦上添花)**
  - 支援圖片上傳，讓食譜展示更豐富。
  - 勾選材料功能，外出採買時可做 Check。
